# 教学经验总结

## 模拟业务场景

@何李健 多次提到希望可以知道怎么用，实际上就是我们说的怎么把**业务场景**转化成代码逻辑。单独讲语言容易把课程变成技术性操作，从@田锃 上的入门课中体现了这个问题。这样上课容易让学生觉得“我听了都懂，一到写就什么都不会，而且感觉学了没什么用”的常规问题。这也是我国高等教育和职业教育行业存在的普遍问题。

如何解决问题呢？选择一个合适的业务场景，并且抽象其中核心简单的业务逻辑，做成课程的案例，是一个很好的方案。对于我们的课程，我们可以把**课程运营的业务逻辑**作为教学用的**业务场景示例**，分析如何用简单的Python语言表达核心的业务逻辑，并且通过后续的Django课程和数据分析把他们变成**生产**上可以使用的业务或者分析代码。

灵感来源于内部教学过程中用助研项目的业务需求来做教学案例。首先，助研项目的业务逻辑和课程APP运营的业务逻辑有很多相似之处，都是内外部成员、有用户组，涉及到一些简单的任务分配和状态管理。其次，由于内培对象都对助研项目有了解，这个业务场景他们有贴身体会；而对于我们未来的用户来说，他们直接能够感受到的业务场景也是我们的课程运营体系，这样不仅可以提高教学效果，还可以顺便让用户增进对我们的了解、对我们更信任。

在内部教学过程中，我没有直接让他们使用Django或者Pandas，而是使用最基本的Python数据结构，比如list、dict，来表达核心的业务逻辑，也就是助研名单、助研分组、任务列表等数据和任务分配等过程。而后续如果使用Django或者Pandas，就换成对应的框架数据结构和标准化的业务流程。这样既可以让课程之间关联性更强，从而实现更好的教学效果和更好的引流效果，让商业逻辑和教学规律完美统一。
