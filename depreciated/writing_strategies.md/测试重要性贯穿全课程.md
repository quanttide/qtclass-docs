## 测试重要性贯穿全课程
目前大厂在作开发时，许多程序员并没养成测试的习惯，这样有时可能会出现不可预知的问题，给其他开发者或者用户造成很大的困扰。因此在我们的教程写作中应将测试重要性贯穿全课程，帮助读者树立对测试的敬畏心。

具体在教程写作过程之中可以穿插痛心疾首的生产案例，素材库如下：

### 素材库
### 1、if条件语句错误
在使用微信云托管CLI工具时，无论在传入--noConfirm或者不传入的情况下都是都无法跳过“发布确认”。翻阅0.0.2版本源码，deploy.js的65行找到了代码逻辑如下：

``` js
if (!flags.noConfirm || (await cli_ux_1.cli.confirm("确定发布？(请输入yes或no)"))) {
    const zipFile = `.cloudrun_${serviceName}_${Date.now()}.zip`;
    const srcPath = path.resolve(process.cwd(), args.path);
    const destPath = path.resolve(process.cwd(), zipFile);
    await zip_1.zipDir(srcPath, destPath);
    console.log(buildInfo);
    await files_1.uploadVersionPackage(buildInfo.UploadUrl, fs.readFileSync(zipFile));
    const createResult = await api_1.SubmitServerRelease(newReleaseConfig);
    await fs.promises.unlink(destPath);
    console.log("触发部署成功，请前往控制台查看详情。");
    cli_ux_1.cli.url("点击前往控制台", `https://cloud.weixin.qq.com/cloudrun/service/${newReleaseConfig.ServerName}`);
}
else {
    console.log("取消发布");
}
```

果哥发现判断语句不对劲，于是把第一个判断语句的！注释掉，然后发现代码按预想的可以跳过确认阶段了。果哥联系了微信云托管的开发者，最后发现是默认值写错了。

``` js
override: command_1.flags.boolean({
    description: "缺省的参数是否沿用旧版本配置",
    default: false,
}),
noConfirm: command_1.flags.boolean({
    description: "发布前是否跳过二次确认",
    default: true,
}),
```
如上所示，无论在传入--noConfirm或者不传入的情况下值都是true，所以会在控制台询问是否发布，改为false就ok了。
